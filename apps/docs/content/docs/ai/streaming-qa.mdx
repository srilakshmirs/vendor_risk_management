The `/ask` endpoint is the system's single most memorable demo beat — the moment that turns "another dashboard" into "an AI-powered analyst."

You type *"Which vendors have CRITICAL risk and handle PII?"* — within a second, citations appear in the right sidebar; within seconds after that, the answer streams in with every vendor reference rendered as a clickable `[V0276]` link.

## How it works

```text
1. User question  →  fastembed (384-dim ONNX)  →  embedding vector
2. embedding vector  →  pgvector cosine top-K  →  K vendor profiles
3. K profiles  →  templated prompt  →  LLM.stream()
4. SSE: event="citations" (immediate)  →  event="token" (deltas)  →  event="done"
```

Three components, each in its own module:

| File | Responsibility |
|---|---|
| `apps/api/src/vrm_api/rag/embedder.py` | fastembed singleton, lazy ONNX model load |
| `apps/api/src/vrm_api/rag/indexer.py` | builds the vendor profile chunks, upserts into `embeddings` table |
| `apps/api/src/vrm_api/rag/retriever.py` | pgvector cosine top-K query |
| `apps/api/src/vrm_api/rag/prompts.py` | TPRM-analyst system prompt + user-prompt assembly |
| `apps/api/src/vrm_api/routers/ask.py` | The three endpoints |

## Embeddings

We use **BAAI/bge-small-en-v1.5** via fastembed:

- 384-dim
- ONNX runtime (no PyTorch dep)
- ~133 MB on disk (cached after first download)
- Local — no network, no API keys

This is a deliberate departure from Ollama / Anthropic. See [Architecture → LLM Providers](/docs/architecture/llm-providers) for why.

## Indexing

One chunk per vendor. The chunk packs every signal the retriever might match against:

```text
V0276 Wade-Barrett SAS (CloudProvider, UK, Tier2)
Annual spend: $500,000.
Data access: FullAdmin to PaymentsAPI, CoreBanking.
Data classes handled: PII, Financial.  GDPR: compliant.
Certifications: SOC2=Expired; ISO27001=Certified; PCI-DSS=Pending.
EXPIRED CERTIFICATIONS: SOC2.
Breach history: 1 event(s) in 12mo; latest 2026-06-08 severity=Critical;
  data exposed: PHI, PII.
Financial health: 35/100.  Preliminary risk: 88/100.
Contract: 2024-03-15 → 2027-03-14, value $1,500,000.
Latest risk assessment: score 85/100, severity CRITICAL,
  anomaly=BREACHED_VENDOR_HIGH_ACCESS.
Narrative: Wade-Barrett SAS — CRITICAL: ...
```

Re-run after seeding:

```bash
make ask-reindex
```

Drops + re-inserts every `vendor` embedding (~10 s for 400 vendors).

## Retrieval

```sql
SELECT entity_id, chunk, vector <=> :query_vec AS distance
FROM embeddings
WHERE entity_type = 'vendor'
ORDER BY distance
LIMIT 8;
```

`<=>` is pgvector's cosine-distance operator. The HNSW index on `vector_cosine_ops` makes this O(log n) — sub-millisecond on 400 vectors, scales to millions.

## The system prompt

```
You are the Société Générale Third-Party Risk Management (TPRM) analyst assistant.
Your job is to answer questions about the vendor portfolio using ONLY the vendor
context blocks provided below.

Rules:
1. Cite every vendor you reference using its ID in square brackets, e.g. [V0123].
2. If the answer requires data not present in the context, say so explicitly —
   do not invent vendors, breaches, scores, or certifications.
3. Be terse and structured.
4. Severity ranking: CRITICAL > HIGH > MEDIUM > LOW > NONE.
5. Compliance vocabulary: SOC 2, ISO 27001, PCI-DSS, GDPR Article 28/33,
   NIST SP 800-53 SA-9, SOX 404.
```

The "cite every vendor using `[V0123]`" rule is what makes the frontend's clickable-link rendering work — the SSE consumer parses these markers and renders them as Next.js `Link`s.

## SSE event format

```text
event: citations
data: {"chunks": [{"vendor_id": "V0276", "similarity": 0.68, "chunk": "..."}, ...]}

event: token
data: **CR

event: token
data: ITICAL P

event: token
data: II vendors:

event: done
data: {"ok": true, "tokens_estimate": 175}
```

**Citations** are emitted **first**, so the right sidebar populates immediately and the user has something to look at while the LLM streams.

> **SSE gotcha**: `sse-starlette` emits `\r\n` line endings. The frontend `consumeSSE` parser normalises `\r\n → \n` before splitting on `\n\n` — without this fix, no events parse. (Already handled.)

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/ask` | Synchronous variant. Returns `{answer, citations, model, provider}`. |
| `POST` | `/ask/stream` | SSE stream — `citations` event then `token` deltas then `done`. |
| `POST` | `/ask/reindex` | Rebuild embeddings for every vendor. |

### Example payload

```bash
curl -X POST http://localhost:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "Which vendors have CRITICAL risk and handle PII?", "k": 8}'
```

```json
{
  "answer": "**CRITICAL PII vendors:**\n- [V0276] Wade-Barrett SAS — Critical breach on 2026-06-08...\n- [V0007] Mayo-Bowman Ltd — password dump...",
  "citations": [

    {"vendor_id": "V0007", "similarity": 0.673, "chunk": "..."}
  ],

  "provider": "ollama"
}
```

## Why this design wins

- **Citations-first SSE** — perceived latency drops from "5 seconds of nothing" to "instant feedback, then streaming text"
- **Pure SQL retrieval** — pgvector queries are explainable; no opaque "vector DB magic"
- **Deterministic indexer** — re-running produces identical chunks; bisecting issues is straightforward
- **Provider-agnostic** — the same `/ask` works with Ollama, Claude, or mock; switch with one env var
